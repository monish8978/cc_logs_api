# CC Logs API — Official API Documentation

## 1. Overview
The CC Logs API is a high-concurrency system designed for log ingestion, application version management, and client authentication. It utilizes a microservices-ready architecture with FastAPI, Celery, Redis, and Elasticsearch.

---

## 2. Global Response Formats

The API follows a standardized response structure for all endpoints to ensure consistent integration.

### 2.1 Success Response
Sent for all successful operations (200 OK, 201 Created).
```json
{
  "status": true,
  "message": "Detailed success message",
  "data": {
    "key": "value"
  }
}
```

### 2.2 Error Response
Sent for client errors (4xx) or server errors (5xx).
```json
{
  "status": false,
  "message": "Description of what went wrong",
  "error": "Internal error details or stack trace (if applicable)"
}
```

## 3. Administrative Endpoints (Admin)

### 3.1 Create New Client
`POST /admin/create-client`
Used to register a new client and generate an initial access key.

**Request Body:**
| Field | Type | Description |
|---|---|---|
| `client_id` | string | Unique identifier for the client |
| `access_key` | string | Secret key for the client |
| `expiry_date` | string | Expiry in `YYYY-MM-DD HH:MM:SS` |
| `status` | bool/str | `true` for active, `false` for suspended |

---

### 3.2 Rotate Access Key
`POST /admin/rotate-key`
Update the secret access key for an existing client.

**Request Body:**
| Field | Type | Description |
|---|---|---|
| `client_id` | string | Target client ID |
| `new_key` | string | The new secret key |

---

### 3.3 Upload Application Version
`POST /admin/upload-version`
Upload a new build/package for a specific client.

**Content-Type:** `multipart/form-data`

**Form Fields:**
- `version`: (e.g., "2.1.0")
- `client_id`: (Target client)
- `release_notes`: (HTML or Text)
- `mandatory`: (0 or 1)
- `file`: (Binary file)

## 4. Logging & Monitoring

### 4.1 Push Log (High Concurrency)
`POST /push-log/`
This endpoint offloads the processing to a Celery worker. It is highly optimized for performance.

**Request Body:**
Accepts any JSON object containing log details (timestamp, level, message, agentId, etc.).

---

### 4.2 Search Logs
`GET /search-logs/`
Query Elasticsearch for specific logs.

**Query Parameters:**
- `agentId`: Filter by agent
- `level`: INFO, ERROR, WARNING, etc.
- `start_date`: YYYY-MM-DD
- `end_date`: YYYY-MM-DD
- `page`: Pagination page number
- `size`: Logs per page

## 5. Client Integration Endpoints

### 5.1 Validate Access Key
`POST /validate-key`
Validates the key and returns a secure, time-limited S3 download URL for the latest app version.

**Request Body:**
```json
{
  "access_key": "your_secret_key"
}
```

---

### 5.2 Check for Updates
`POST /check-version`
Used by client applications to verify if a newer version is available.

**Request Body:**
```json
{
  "client_id": "test_client",
  "current_version": "1.0.0"
}
```

## 6. HTTP Status Codes

| Code | Meaning |
|---|---|
| `200` | OK - Request was successful |
| `201` | Created - Resource was successfully created |
| `400` | Bad Request - Invalid parameters |
| `401` | Unauthorized - Invalid or expired access key |
| `404` | Not Found - Resource does not exist |
| `409` | Conflict - Resource already exists (e.g., duplicate client_id) |
| `500` | Internal Server Error - Unexpected server issue |
